오류를 제보할 때, 스크린샷보다 재현 순서를 먼저 적으세요

오류를 만난 사람이 같은 상황을 안전하게 재현하도록 시작 조건, 최소 단계, 기대 결과와 실제 결과를 분리해 적는 방법입니다.

도구생활 편집부 · 2026-11-19 · 2분 읽기NEW조회 0 (매시간 반영)

이 글의 목차

  1. 시작 조건과 수행 순서를 나누세요
  2. 기대한 결과와 본 결과를 한 줄씩 적으세요
  3. 비교 결과가 있다면 마지막에 붙이세요

“저장 버튼이 안 돼요”에 화면 사진만 붙이면 받은 사람은 어느 문서에서 무엇을 눌러야 하는지부터 다시 묻게 됩니다. 오류를 처음 보는 사람에게는 완성된 설명보다 같은 지점에 도달할 수 있는 짧은 길이 필요합니다. 제보의 첫 줄에는 무엇을 하려다 어디서 막혔는지 적으세요. 예를 들어 “양식에 항목 두 개를 입력한 뒤 임시 저장을 누르면 두 번째 항목이 사라집니다”처럼요.

시작 조건과 수행 순서를 나누세요 #

빈 양식인지 복사한 양식인지, 기존 파일인지 새 파일인지처럼 결과를 바꿀 수 있는 조건을 먼저 적습니다. 이어 “새 양식 열기 → 예시 항목 두 줄 입력 → 임시 저장 → 다시 열기”처럼 실제로 한 행동만 순서대로 적으세요. 이미 알고 있는 원인이라고 단정하지 말고, 확인한 동작을 적는 게 먼저입니다. 개인정보나 업무 원본이 필요 없는 경우에는 연습용 데이터로 바꾸고, 실제 제출이나 결제가 일어나는 과정은 테스트 환경에서만 재현하세요.

기대한 결과와 본 결과를 한 줄씩 적으세요 #

“기대: 저장 후 항목 두 줄이 모두 남음. 실제: 첫 줄만 남음.” 이렇게 분리하면 화면이 제대로 열렸는지와 내용이 저장됐는지를 혼동하지 않습니다. 메시지가 떴다면 필요한 오류 문구만 옮기고, 같은 조건에서 세 번 시도해 두 번 발생했다면 그 횟수를 적으세요. 한 번만 본 경우에는 “한 번 관찰, 반복 여부 미확인”이면 충분합니다.

비교 결과가 있다면 마지막에 붙이세요 #

첫 항목만 넣었을 때는 정상이고 두 줄부터 문제가 나타났다면, 그 차이가 긴 영상보다 유용할 수 있습니다. 캡처는 위 순서로 설명하기 어려운 상태를 보여줄 때만 덧붙이고 공유해도 되는 정보인지 확인하세요. 다음에 제보할 때는 양식에 ‘시작 조건 / 재현 순서 / 기대 / 실제’ 네 칸만 만들고, 동료가 추가 질문 없이 같은 지점까지 갈 수 있는지 먼저 읽어 보세요.

조회수는 외부 서비스로 집계하며 새로고침·봇 요청이 포함될 수 있습니다.

함께 읽으면 좋은 글

  • 시작한 일이 너무 많다면, 새로 시작할 조건을 정해 보세요
  • 작은 자동화를 넘겨줄 때는 실행 방법보다 멈추는 방법부터 적으세요
  • 답변을 기다리는 일은 내 할 일과 다른 목록에 두세요
