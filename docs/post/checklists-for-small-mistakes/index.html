반복되는 작은 실수, 체크리스트는 짧을수록 쓰기 쉽습니다

실제로 놓친 항목과 확인 시점을 연결하고, 완료 여부를 관찰할 수 있는 문장으로 체크리스트를 만드세요.

첨부 파일을 빠뜨리거나 문서 날짜를 고치지 않은 채 보내는 일은 알고도 반복될 수 있습니다. 이런 실수를 막으려고 확인 항목을 계속 늘리면 목록 자체를 읽지 않게 되기도 합니다. 체크리스트는 업무 지식을 전부 옮겨 놓은 설명서가 아니라 특정 순간에 놓치기 쉬운 내용을 되짚는 장치입니다. 최근 실제로 발생한 실수부터 작게 다루는 편이 실용적입니다.

실수와 확인 시점을 짝지으세요 #

먼저 무엇을 빠뜨렸는지와 어느 시점에 확인했으면 막을 수 있었는지를 적습니다. 파일 전송 실수라면 문서를 만드는 단계보다 보내기 직전 확인이 더 효과적일 수 있습니다. 예를 들어 ‘수신 대상 확인, 파일 열림 확인, 날짜 확인’처럼 실제 위험에 맞춰 항목을 정하세요. 모든 업무에 하나의 거대한 목록을 쓰기보다 제출, 회의 준비, 자료 공개처럼 행동이 바뀌는 지점별로 나누면 필요한 순간에 찾기 쉽습니다. 기억이 나지 않는 위험을 상상해 끝없이 추가하기보다 반복되는 문제부터 반영합니다.

눈으로 확인할 수 있게 쓰세요 #

‘꼼꼼히 검토’나 ‘오류 없이 제출’은 끝났다고 판단하기 어렵습니다. ‘첨부한 파일을 열어 내용 확인’처럼 실제 행동이 보이는 문장으로 바꾸세요. 금액이나 대상 이름처럼 중요한 항목은 무엇과 대조할지도 정합니다. 이전 문서에서 복사한 날짜를 확인한다면 현재 일정표와 비교하는 방식입니다. 단순히 체크 표시를 하는 행위가 검증을 대신하지 않도록 항목은 구체적이어야 합니다. 반복 작업을 도구로 검사할 수 있는 부분이 있어도 사람의 판단이 필요한 항목까지 자동으로 통과시켰다고 가정하지 않습니다.

쓰이지 않는 항목은 다시 고르세요 #

몇 번 사용한 뒤 실제로 도움이 된 항목과 습관적으로 넘긴 항목을 살펴봅니다. 중요하지 않은 내용은 줄이고, 의미를 여러 번 물어본 항목은 표현을 바꾸세요. 업무 방식이 달라졌다면 오래된 목록도 갱신해야 합니다. 안전이나 법적 절차처럼 공식 확인이 필요한 업무에서는 개인 체크리스트가 정해진 절차를 대신할 수 없으므로 해당 기준을 먼저 따릅니다. 목록을 써도 같은 실수가 반복되면 항목을 더 추가하기 전에 확인 시점이나 작업 환경을 바꿔 보세요. 보내기 버튼 가까이에 두는 짧은 목록이 따로 숨겨 둔 긴 문서보다 자주 쓰일 수 있습니다.
