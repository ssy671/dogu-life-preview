공동 문서의 원본, 파일보다 위치를 함께 관리하세요

어디에서 수정해야 하는지 기준을 정하고, 사본과 원본을 구분해 같은 자료가 따로 바뀌는 일을 줄이세요.

  3. 위치가 바뀔 때 연결과 권한을 확인하세요

공동 문서를 메일로 보내고 다시 내려받아 수정하면 같은 제목의 파일이 여러 곳에 생깁니다. 누구나 자기 파일이 최신이라고 생각하면 수정 사항을 합치는 데 시간이 듭니다. 이 문제는 파일 이름만 잘 정한다고 모두 해결되지는 않습니다. 실제로 수정이 이루어지는 기준 위치와 참고용으로 전달되는 사본을 함께 관리해야 합니다. 원본은 가장 최근에 받은 파일이 아니라 팀이 합의한 기준 자료입니다.

수정할 기준 위치를 정하세요 #

문서를 공동으로 쓰기 시작할 때 수정은 어디에서 할지 정하고 안내 문서나 작업 공간에 연결합니다. 예를 들어 일정표는 공유 문서 한 곳에서 갱신하고, 메일 첨부본은 특정 시점의 참고 자료로 표시할 수 있습니다. 이때 문서 소유자와 변경을 판단하는 담당자도 분명히 하세요. 기준 위치가 여러 곳이라면 각 위치가 담당하는 범위를 구분해야 합니다. 최종 납품본과 계속 바뀌는 운영 원본이 따로 존재하는 것은 가능하지만 두 파일이 같은 역할을 한다고 안내하면 혼란이 생깁니다.

사본에는 상태와 기준 시점을 남기세요 #

외부 제출이나 오프라인 확인 때문에 사본이 필요한 경우도 있습니다. 사본에는 어느 시점의 내용인지와 수정 제안을 어디로 보내야 하는지 적어 두세요. 예를 들어 ‘10월 검토용 사본, 수정은 공유 원본에 반영’이라고 설명하면 역할이 드러납니다. 사본에서 작업해야 하는 상대라면 변경 내용을 되돌려 받는 방법도 정합니다. 문서 내부 링크, 파일 이름, 전달 메시지 중 한 곳에만 설명을 넣으면 맥락이 사라질 수 있으므로 실제로 파일을 보는 사람이 기준을 확인할 수 있어야 합니다. 사본을 만들지 않는 것보다 사본의 역할을 분명히 하는 것이 중요합니다.

위치가 바뀔 때 연결과 권한을 확인하세요 #

파일을 다른 폴더나 계정으로 옮기면 기존 링크가 유지되는지는 도구에 따라 다를 수 있습니다. 이동 후에는 안내 문서의 연결과 관련자의 접근 권한을 실제로 확인하세요. 링크를 가지고 있다는 이유만으로 편집이 가능한 것은 아니며, 반대로 공개 범위가 의도보다 넓어질 수도 있습니다. 담당자가 바뀌면 개인 계정에만 소유권이 묶이지 않았는지도 살펴봅니다. 조직에서 정한 이관 규칙이 있다면 그 절차를 우선합니다. 원본 위치를 관리한다는 것은 파일 주소 하나를 저장하는 일이 아니라 누가 어디에서 어떤 내용을 바꿀 수 있는지 유지하는 일입니다.
