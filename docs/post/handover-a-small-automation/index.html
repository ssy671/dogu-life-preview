작은 자동화를 넘겨줄 때는 실행 방법보다 멈추는 방법부터 적으세요

자동화의 입력, 결과, 정상 판정과 중단·수동 복구 절차를 정리해 다른 사람이 관리할 수 있게 만듭니다.

도구생활 편집부 · 2026-11-15 · 2분 읽기NEW조회 0 (매시간 반영)

이 글의 목차

  1. 무엇을 읽고 무엇을 바꾸는지 적으세요
  2. 성공 메시지와 실제 결과를 연결하세요
  3. 재실행 전에 확인할 조건을 쓰세요

자동화를 만든 사람이 자리를 비웠을 때 가장 어려운 질문은 ‘어떻게 실행하나요’보다 ‘지금 정상인가요, 다시 실행해도 되나요’일 수 있습니다. 실행 버튼만 알려주면 중복 처리나 잘못된 결과를 놓치기 쉽습니다. 짧은 운영 메모에 정상 판단과 중단 방법까지 넣어 두세요.

무엇을 읽고 무엇을 바꾸는지 적으세요 #

입력 파일이나 시스템, 실행 시점, 결과가 저장되는 위치를 기록합니다. 조회만 하는 작업과 데이터를 변경하거나 알림을 보내는 작업을 구분하세요. 필요한 권한은 역할 중심으로 설명하고 암호나 토큰을 운영 메모에 붙여 넣지는 않습니다. 민감한 입력이 외부로 전달되는지도 확인해야 합니다.

성공 메시지와 실제 결과를 연결하세요 #

정상 종료 메시지만으로 업무가 끝났다고 판단하지 않도록 확인할 결과를 정합니다. 예를 들어 ‘행 10개를 읽었고 중복을 제외한 8개가 저장됐다’처럼 입력과 출력 수를 비교할 수 있습니다. 마지막 정상 실행 시각과 오류 기록을 어디에서 보는지도 남기세요.

재실행 전에 확인할 조건을 쓰세요 #

같은 입력을 다시 실행하면 덮어쓰는지, 중복 생성하는지 또는 아무 변화가 없는지 사본으로 시험해 기록합니다. 동작을 확신할 수 없다면 무조건 재시도하도록 안내하지 않습니다. 예약 실행을 멈추는 위치, 중간 결과의 처리 방식, 수동으로 이어갈 순서를 정한 뒤 인수인계받는 사람이 작은 예제로 따라 해 보도록 합니다. 전체 설계보다 실제로 멈추고 복구할 수 있는지가 관리 가능성을 보여 줍니다.

조회수는 외부 서비스로 집계하며 새로고침·봇 요청이 포함될 수 있습니다.

함께 읽으면 좋은 글

  • 답변을 기다리는 일은 내 할 일과 다른 목록에 두세요
  • 결정이 자꾸 되풀이된다면, 결론 옆에 바꿀 조건을 적어 보세요
  • 반복되는 작은 실수, 체크리스트는 짧을수록 쓰기 쉽습니다
