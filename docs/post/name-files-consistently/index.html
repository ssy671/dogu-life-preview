‘최종_진짜최종’ 대신, 다시 찾기 쉬운 파일 이름 짓기

날짜, 목적, 버전을 같은 순서로 적으면 파일 이름만 보고도 필요한 문서를 고르기 쉬워집니다.

도구생활 편집부 · 2026-10-14 · 3분 읽기NEW조회 1 (매시간 반영)

문서의 내용은 기억나는데 파일 이름이 떠오르지 않는 순간이 있습니다. 이름에 ‘최종’이라는 말만 여러 번 붙어 있으면 문서를 열어 확인하는 일이 반복됩니다. 파일 이름은 저장할 때의 상황을 기록하는 동시에, 나중에 찾을 사람에게 설명을 남기는 역할을 합니다. 중요한 것은 멋진 규칙보다 반복해서 쓸 수 있는 간단한 규칙입니다.

날짜와 목적의 순서를 정하세요

시간 순서가 중요한 자료라면 ‘연도-월-일_목적’처럼 날짜를 먼저 쓸 수 있습니다. 예를 들어 ‘2026-10-14_주간회의록’은 이름으로 정렬했을 때 순서를 파악하기 쉽습니다. 날짜를 쓸 때에는 자릿수를 통일해야 합니다. 월과 일을 두 자리로 적으면 이름의 형태도 일관됩니다.

목적을 먼저 떠올리는 업무라면 ‘프로젝트_문서종류_날짜’라는 순서가 더 편할 수 있습니다. ‘홈페이지개편_요구사항_2026-10-14’처럼 적는 방식입니다. 날짜가 작성일인지 회의일인지도 팀에서 합의하는 편이 좋습니다. 두 날짜가 꼭 필요하지 않다면 하나만 사용하고 그 의미를 명확히 정합니다.

버전과 상태를 구분하세요

작업 파일에 버전을 붙이는 경우 ‘v01’, ‘v02’처럼 숫자의 자릿수를 맞출 수 있습니다. 버전이 바뀌는 기준은 간단하게 정해 둡니다. 외부에 전달한 뒤 수정하는 경우에만 올리는지, 중요한 내용이 바뀔 때마다 올리는지를 합의하면 이름이 덜 혼란스럽습니다. 공동 편집 도구에 버전 기록이 있다면 파일 이름에 모든 수정 이력을 넣을 필요는 없습니다.

검토용인지 제출용인지 표시해야 한다면 상태 표현도 제한하는 것이 좋습니다. ‘초안’, ‘검토’, ‘제출’ 정도의 공통 용어를 정하고 같은 의미로 사용합니다. ‘최종’이라는 단어가 반드시 나쁜 것은 아니지만, 최종본을 다시 수정했을 때 어떤 기준을 적용할지까지 정해야 합니다.

공유하는 환경의 제약을 확인하세요

파일 이름에는 운영체제나 공유 서비스가 허용하지 않는 문자가 있을 수 있습니다. 특정 문자를 꼭 써야 하는 것이 아니라면 단순한 구분 기호를 선택하고 실제 환경에서 열리는지 확인합니다. 지나치게 긴 이름은 경로를 다루는 도구에서 문제가 되거나 화면에서 끝이 잘릴 수 있으므로 핵심 정보만 담는 편이 좋습니다.

오늘 자주 사용하는 문서 세 개를 골라 같은 순서로 이름을 정해 보세요. 다음에 찾을 때 필요한 정보가 충분한지 확인한 후 규칙을 문장 한 줄로 적어 둡니다. 공유 문서의 이름을 바꿀 때에는 링크와 자동화 작업에 영향이 있는지도 살펴야 합니다. 작은 규칙이라도 함께 일하는 사람이 쉽게 설명할 수 있다면 오래 유지하기 좋습니다.

조회수는 외부 서비스로 집계하며 새로고침·봇 요청이 포함될 수 있습니다.
