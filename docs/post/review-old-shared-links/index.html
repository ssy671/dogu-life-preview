예전에 만든 공유 링크, 아직 열려 있어야 할까요

새 링크를 보내는 방법보다, 오래된 공개 링크를 찾아 목적과 접근 범위를 다시 확인하는 방법에 집중합니다.

도구생활 편집부 · 2026-10-22 · 3분 읽기NEW조회 0 (매시간 반영)

이 글의 목차

  1. 먼저 외부에 전달한 자료를 모으세요
  2. 종료와 축소를 나누어 판단하세요
  3. 바꾼 뒤 실제 사용 경로를 점검하세요

자료를 전달할 때 만든 공유 링크는 일이 끝난 뒤에도 남을 수 있습니다. 문서 자체를 정리했더라도 예전 메신저나 메일에서 링크를 열 수 있다면 접근 범위는 그대로일 수 있습니다. 공유 링크 정리는 링크를 예쁘게 모으는 작업이 아니라, 누가 어떤 자료를 언제까지 볼 필요가 있는지 되짚는 일입니다.

먼저 외부에 전달한 자료를 모으세요 #

전체 계정의 링크를 한 번에 찾으려 하면 시작하기 어렵습니다. 최근 끝난 프로젝트 하나를 고르고, 외부에 보냈던 제안서와 일정표, 결과물부터 확인합니다. 사용하는 서비스에서 공유 상태를 확인할 수 있는 경우 그 정보를 참고하고, 보낸 메일이나 대화 기록도 함께 살펴봅니다. 제목만으로 내용을 알기 어렵다면 실제 문서를 열어 대상을 확인하세요.

목록에는 문서 이름, 원본 위치, 공유 대상, 공유 목적, 검토할 날짜를 적습니다. 링크 주소만 잔뜩 저장하면 어떤 권한이 필요한지 판단하기 어렵습니다. 예를 들어 행사 참가자 안내와 내부 정산표는 같은 프로젝트 자료여도 접근해야 할 사람이 다릅니다. 내부 자료가 외부 링크로 연결되어 있지 않은지도 확인합니다.

종료와 축소를 나누어 판단하세요 #

프로젝트가 끝났다고 모든 공유를 바로 끊을 필요는 없습니다. 상대방이 결과물을 인수하거나 정산을 확인하는 기간이 남아 있을 수 있습니다. 계속 필요한 자료는 대상과 권한을 좁히고, 필요가 끝난 링크는 접근을 종료하는 식으로 구분합니다. 조직의 보존 규칙이나 계약상 제공 기간이 있다면 그 기준을 먼저 적용하세요.

‘링크를 아는 사람’에게 열려 있는지, 지정한 계정만 열 수 있는지, 편집까지 가능한지 살펴보세요. 공동 작업자가 관리하는 링크는 혼자 바꾸기 전에 영향을 확인해야 합니다. 접근을 닫아도 상대가 이미 내려받은 사본까지 없어지는 것은 아니므로, 링크 해제를 자료 회수와 같은 뜻으로 생각하면 안 됩니다.

바꾼 뒤 실제 사용 경로를 점검하세요 #

권한을 변경했다면 필요한 사람이 여전히 자료를 열 수 있는지 확인합니다. 업무에 쓰는 안내 문서가 옛 링크를 참조한다면 새 경로로 고칩니다. 다만 외부에 공개하면 안 되는 자료를 시험한다며 다른 공개 계정에 다시 공유하는 방식은 피하세요. 권한 화면과 조직에서 허용한 확인 방식으로 검증하면 됩니다.

다음부터는 링크를 만들 때 검토 시점도 함께 기록해 보세요. 행사 종료 후, 계약 마무리 후처럼 업무 사건에 연결하면 날짜를 임의로 정하는 것보다 관리하기 쉽습니다. 링크가 필요한 기간과 실제로 열려 있는 기간을 맞추는 작은 습관이 오래된 공유를 줄여줍니다.

조회수는 외부 서비스로 집계하며 새로고침·봇 요청이 포함될 수 있습니다.
